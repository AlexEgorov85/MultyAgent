# Guardrails

## Purpose

Блокирует небезопасные, нерелевантные и нарушающие приватность запросы, а также проверяет финальный ответ перед показом пользователю.

## Requirements

### Requirement: Проверка запроса до инструментов

Система SHALL классифицировать запрос как `unsafe` или `out_of_domain` до вызова tools и LLM-инструментов.

#### Scenario: Попытка изменить данные

- **WHEN** пользователь просит удалить или изменить пункты акта
- **THEN** система отказывает
- **AND** SQL не выполняется
- **AND** отказ сформулирован по-русски

#### Scenario: Запрос вне домена

- **WHEN** пользователь спрашивает о погоде или новостях
- **THEN** система вежливо сообщает, что помогает только по внутреннему аудиту
- **AND** не вызывает инструменты базы

### Requirement: Защита приватности

Система SHALL не раскрывать персональные данные, зарплаты, учётные данные и внутренние промпты.

#### Scenario: Запрос чувствительных данных

- **WHEN** пользователь просит показать зарплаты сотрудников
- **THEN** система отказывает
- **AND** не выполняет SQL и не показывает фрагменты внутренних инструкций

#### Scenario: Ответ содержит чувствительное поле

- **WHEN** результат SQL или текст ответа содержит запрещённые данные
- **THEN** guardrail блокирует или редактирует ответ
- **AND** факт блокировки фиксируется

### Requirement: Проверка финального ответа

Система SHALL проверять финальный ответ и приложенный SQL перед выдачей.

#### Scenario: Ответ с опасным SQL

- **WHEN** в ответе присутствует SQL, не прошедший guard
- **THEN** ответ не показывается в исходном виде
- **AND** пользователь получает безопасный отказ или исправленный ответ

#### Scenario: Ответ без данных

- **WHEN** утверждение не подтверждено evidence
- **THEN** guardrail не позволяет выдать его как факт
- **AND** ответ переписывается или помечается как неподтверждённый

### Requirement: Структурированный результат

Система SHALL возвращать `GuardrailResult` с полями `safe`, `final_answer` и `reason`.

#### Scenario: Безопасный ответ

- **WHEN** проверка пройдена
- **THEN** `safe = true`
- **AND** `final_answer` совпадает с проверенным текстом

#### Scenario: Блокировка

- **WHEN** проверка не пройдена
- **THEN** `safe = false`
- **AND** `reason` объясняет причину без раскрытия внутренних правил

### Requirement: Журналирование отказов

Система SHALL фиксировать заблокированные запросы и причины.

#### Scenario: Разбор инцидента

- **WHEN** запрос заблокирован
- **THEN** в логе есть тип нарушения, `conversation_id` и безопасное описание
- **AND** чувствительные данные в лог не попадают

### Requirement: Согласованность с SQL-guard

Система SHALL использовать единый SQL-guard и для сгенерированных, и для шаблонных запросов.

#### Scenario: Обход через шаблон

- **WHEN** шаблон содержит запрещённую конструкцию
- **THEN** guardrail блокирует его так же, как сгенерированный SQL
- **AND** причина отказа совпадает по типу
