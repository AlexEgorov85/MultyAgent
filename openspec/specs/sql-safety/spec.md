# SQL Safety

## Purpose

Гарантирует, что любой SQL, построенный моделью или взятый из шаблона, выполняется только как одиночный read-only запрос с ограниченным доступом к схеме и строкам.

## Requirements

### Requirement: Только одиночный read-only SELECT

Система SHALL отклонять любой SQL, который не является ровно одним запросом `SELECT` (включая `WITH`), до его выполнения.

#### Scenario: Разрешённый запрос

- **WHEN** SQL содержит один `SELECT` или `WITH ... SELECT` по разрешённой таблице
- **THEN** проверка проходит
- **AND** запрос передаётся на выполнение

#### Scenario: Несколько statements

- **WHEN** SQL содержит `SELECT 1; DROP TABLE audit.acts`
- **THEN** запрос отклоняется как содержащий более одного statement
- **AND** ничего не выполняется

#### Scenario: Изменяющая операция

- **WHEN** SQL содержит `INSERT`, `UPDATE`, `DELETE`, `DROP`, `CREATE`, `ALTER`, `TRUNCATE`, `COPY`, `CALL` или `DO`
- **THEN** запрос отклоняется с указанием запрещённой операции

### Requirement: Allowlist схемы и объектов

Система SHALL разрешать обращения только к схеме `audit`, её таблицам и представлениям из утверждённого списка.

#### Scenario: Чужая схема

- **WHEN** запрос обращается к `public.pg_authid` или `information_schema.tables`
- **THEN** запрос отклоняется
- **AND** причина содержит имя запрещённой схемы

#### Scenario: Системный каталог

- **WHEN** запрос содержит `pg_catalog`, `pg_read_file`, `pg_sleep` или `COPY ... FROM PROGRAM`
- **THEN** запрос отклоняется
- **AND** попытка фиксируется в логе

#### Scenario: Неизвестная таблица

- **WHEN** имя таблицы отсутствует в allowlist и не является CTE
- **THEN** запрос отклоняется
- **AND** CTE с тем же именем не считается таблицей БД

### Requirement: Ограничение объёма результата

Система SHALL гарантировать, что выполненный запрос не вернёт больше `MAX_ROWS` строк.

#### Scenario: Нет LIMIT

- **WHEN** валидный запрос не содержит `LIMIT`
- **THEN** к запросу добавляется `LIMIT MAX_ROWS`

#### Scenario: Слишком большой LIMIT

- **WHEN** запрос содержит `LIMIT 100000` при `MAX_ROWS = 200`
- **THEN** лимит уменьшается до 200
- **AND** ответ сообщает, что показано не более 200 строк

### Requirement: Изоляция выполнения

Система SHALL выполнять пользовательский SQL под read-only ролью с таймаутом и без права записи.

#### Scenario: Превышение времени

- **WHEN** запрос выполняется дольше `SQL_TIMEOUT_SEC`
- **THEN** выполнение прерывается
- **AND** пользователь получает сообщение с предложением уточнить фильтр

#### Scenario: Попытка записи на уровне БД

- **WHEN** guard пропустил запрос, но PostgreSQL получил операцию записи
- **THEN** read-only транзакция отклоняет операцию
- **AND** ответ не маскирует ошибку под успешный результат

### Requirement: Безопасные готовые шаблоны

Система SHALL выполнять шаблоны из `script_templates` только через bind-параметры и SHALL прогонять их через тот же SQL-guard.

#### Scenario: Подстановка параметров

- **WHEN** шаблон получает значение `year = 2026`
- **THEN** значение передаётся драйверу как параметр
- **AND** не склеивается с текстом SQL

#### Scenario: Некорректный параметр

- **WHEN** обязательный параметр отсутствует или имеет неверный тип
- **THEN** шаблон не выполняется
- **AND** возвращается ошибка валидации параметров

#### Scenario: Небезопасный шаблон

- **WHEN** текст шаблона не проходит allowlist или содержит запрещённую операцию
- **THEN** шаблон блокируется на этапе проверки
- **AND** это фиксируется как дефект конфигурации

### Requirement: Проверка финального ответа

Система SHALL повторно проверять SQL и ответ перед показом пользователю.

#### Scenario: Guardrail видит отклонённый SQL

- **WHEN** в финальном ответе присутствует SQL, не прошедший guard
- **THEN** ответ блокируется или переписывается без выполнения
- **AND** причина отказа попадает в лог

### Requirement: Регрессионные тесты безопасности

Система SHALL содержать тесты, подтверждающие блокировку опасных конструкций и пропуск корректных запросов.

#### Scenario: Набор «злых» запросов

- **WHEN** запускаются тесты `sql_guard`
- **THEN** блокируются как минимум: `DELETE`, `DROP`, `; --`, `COPY ... FROM PROGRAM`, `pg_read_file`, `pg_sleep`, `UNION` с `pg_catalog`, `information_schema`, обращение к чужой схеме
- **AND** обычный `SELECT` по разрешённой таблице проходит
