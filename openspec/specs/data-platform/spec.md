# Data Platform

## Purpose

Обеспечивает воспроизводимый жизненный цикл PostgreSQL, безопасные миграции, разделение прав и загрузку синтетического набора данных, на котором работают все агенты.

## Requirements

### Requirement: Жизненный цикл встроенного PostgreSQL

Система SHALL запускать PostgreSQL 16 через библиотеку `pgserver` в жизненном цикле backend-приложения и SHALL сохранять его доступным на протяжении всей работы CLI или API.

#### Scenario: Приложение запускает и останавливает сервер

- **WHEN** backend стартует с пустым каталогом `data/pg`
- **THEN** создаётся кластер, применяются миграции, сервер доступен для запросов
- **AND** при штатном завершении backend соединения закрываются, сервер останавливается

#### Scenario: DSN не фиксируется навсегда

- **WHEN** сервер перезапущен и получил другой порт
- **THEN** приложение формирует актуальный DSN при старте
- **AND** не использует устаревший DSN из файла как постоянную настройку

### Requirement: Неразрушающие миграции

Система SHALL применять каждую миграцию не более одного раза, фиксируя имя, checksum и время применения в служебной таблице `public.schema_migrations`.

#### Scenario: Повторный запуск подготовки

- **WHEN** `scripts/init_db.py` запускается повторно на существующей базе
- **THEN** уже применённые миграции пропускаются
- **AND** схема `audit`, таблицы и данные не удаляются

#### Scenario: Изменённая миграция обнаружена

- **WHEN** checksum применённой миграции не совпадает с файлом
- **THEN** подготовка завершается ошибкой с указанием файла
- **AND** изменения в базу не применяются

#### Scenario: Явный сброс

- **WHEN** пользователь запускает отдельную команду сброса с подтверждающим флагом
- **THEN** бизнес-схема пересоздаётся
- **AND** служебный реестр миграций сохраняется или очищается предсказуемо и документированно

### Requirement: Разделение ролей доступа

Система SHALL использовать отдельные роли для чтения бизнес-данных, записи долгосрочной памяти и администрирования.

#### Scenario: Read-only роль не может изменить данные

- **WHEN** подключение `audit_ro` выполняет `INSERT`, `UPDATE`, `DELETE` или DDL
- **THEN** PostgreSQL отклоняет операцию
- **AND** `SELECT` по схеме `audit` и представлениям выполняется успешно

#### Scenario: Агенты не имеют административного доступа

- **WHEN** tool или агент формирует SQL
- **THEN** он использует только read-only подключение
- **AND** административные учётные данные недоступны в коде агентов и в ответах

#### Scenario: Запись памяти и истории ограничена

- **WHEN** приложение сохраняет профиль аудитора или историю чата
- **THEN** запись разрешена только в `audit.auditor_memory`,
  `audit.chat_threads` и `audit.chat_messages`
- **AND** бизнес-таблицы проверок, актов и пунктов для этой роли
  недоступны на запись

### Requirement: Воспроизводимая загрузка seed

Система SHALL загружать синтетический набор идемпотентно: повторная загрузка не создаёт дубликатов и не требует ручной очистки.

#### Scenario: Повторная загрузка того же seed

- **WHEN** CSV из `data/seed` загружаются повторно
- **THEN** количество строк в таблицах не удваивается
- **AND** результат соответствует manifest и checksum

#### Scenario: Загрузка без подготовленного seed

- **WHEN** каталог `data/seed` отсутствует
- **THEN** подготовка схемы завершается успешно
- **AND** система сообщает, что данные не загружены

### Requirement: Совместимость с Windows и кириллическим путём

Система SHALL корректно инициализировать PostgreSQL, если путь к Python-пакетам или профилю пользователя содержит не-ASCII символы.

#### Scenario: `initdb` не может работать с текущим путём

- **WHEN** `initdb` завершается ошибкой кодировки UTF-8
- **THEN** runtime PostgreSQL размещается в ASCII-пути
- **AND** каталог данных проекта может оставаться в исходном расположении
- **AND** README описывает это поведение
