# Визуализация данных

Агент умеет строить диаграмму двумя способами:

- по текущему запросу — «Проведи аналитику по месяцам за последние 2 года
  по закрытым проверкам и выведи в виде диаграммы»;
- по данным предыдущего ответа — «Построй диаграмму на основании этих
  данных», «Покажи это на графике», «Сделай круговую диаграмму».

Визуализацию выбирает LLM, а код проверяет, что она не выдумала данные.
Детерминированного построителя диаграмм нет: если модель недоступна или
вернула точки, которых нет в данных, агент честно сообщает, что диаграмму
построить не удалось.

## Поток

```text
«Проведи аналитику ... и выведи в виде диаграммы»
  → router: analytics_mode=chart
  → analytics/plan → validate → execute:
       обычный QueryPlan + SQL по текущему вопросу
  → analytics/chart:
       строки текущего запроса
       ИЛИ payload предыдущего ответа, если текущий план не построен
  → LLM plan_chart → ChartSpec (bar/line/pie, подписи, точки)
  → grounding: каждая точка должна существовать в строках
  → если точек меньше двух — честный ответ без диаграммы
  → ACL inform: answer + chart
  → presentation: kind=chart
  → UI: ChartView (bar/line/pie)
```

## Текущий запрос или предыдущий ответ

Router вместе с `analytics_mode=chart` возвращает `chart_source`:

- `previous` — визуализировать уже показанные данные. Chart-узел сразу
  читает payload предыдущего ответа, **не запуская новый план/SQL**;
- `current` — в вопросе есть новые условия, метрика или период. Сначала
  выполняется обычный QueryPlan/SQL, диаграмма строится по его строкам.

Если chart-режим получает рабочий QueryPlan, он сначала выполняет обычную
аналитику и строит диаграмму по её строкам. Это покрывает запросы вида
«Проведи аналитику по месяцам ... и выведи в виде диаграммы».

Если план не построен (например, вопрос «Построй диаграмму на основании
этих данных» без новых условий), используется payload предыдущего
аналитического ответа. В `audit.chat_messages` для этого хранятся:

- `rows` — до 200 строк результата;
- `columns`;
- `sql`;
- `question` — вопрос, по которому получены данные;
- `chart` — если ответ уже был диаграммой.

`dialogue_store.load_last_analytics` берёт `payload`, поэтому follow-up
диаграмма строится ровно по тем данным, которые пользователь видел.
Для старых сообщений без payload остаётся fallback: SQL из `trace`.

## ChartSpec

```json
{
  "type": "bar",
  "title": "Закрытые проверки по карманам",
  "subtitle": "За последний год",
  "category": "pocket",
  "category_label": "Карман",
  "value_label": "Количество",
  "unit": "проверок",
  "data": [
    {"label": "2026. Переводы и платежи", "value": 9,
     "row_index": 0, "measure": "cnt"},
    {"label": "2026. Карты и эквайринг", "value": 7,
     "row_index": 1, "measure": "cnt"}
  ]
}
```

`type`: `bar`, `line`, `pie`.

LLM получает вопрос, предыдущий вопрос, колонки и до 40 строк. Промпт
`analytics_chart` требует не выдумывать числа и категории и указывать для
каждой точки `row_index` (номер строки) и `measure` (числовая колонка).
Код через `ground_chart_points` сам берёт значение из строки и сверяет его
с `value`: подпись может быть человеческой («Март 2025»), и это больше не
мешает принять корректную точку. Точки без ссылки на строку сверяются по
паре «категория — значение». Выдуманные точки отбрасываются; если
валидных меньше двух — диаграмма не принимается.

Для `line` точки сортируются по сырому значению колонки `category`
(«2025-03»), а не по подписи: иначе «Август» оказался бы раньше «Марта».

## UI

`ui/app/ChartView.tsx` рисует bar/line/pie без внешних chart-библиотек.
`ui/app/chart.ts` валидирует ChartSpec из API и localStorage.
Chart хранится в сообщении рядом с текстом и trace, поэтому переживает
перезагрузку страницы.

## Ограничения

- Для нового запроса нужен валидный QueryPlan/SQL. Если план не построен,
  используется предыдущий ответ; если и его нет — агент честно просит
  сначала задать аналитический вопрос.
- Для старых сообщений без `payload` используется SQL из trace; SQL
  шаблонов с bind-параметрами может не выполниться повторно.
- UI не поддерживает произвольные Vega/ECharts-спецификации: только
  `bar`, `line`, `pie`.
